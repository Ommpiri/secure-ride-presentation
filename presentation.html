Research Gap & Our Improvement

What was missing — and how this project fills it

Existing Research Gaps

✕All 14 papers address only single-domain detection — never combined across ground, water & aerial.
✕No prior work implements WebSocket-based live IoT dashboard.
✕PIR-based systems fail outdoors due to temperature/humidity sensitivity.
✕Vision-based systems (YOLO, CNN) require GPU — not viable for embedded.
✕Servo-radar designs restricted to a single detection plane only.

Our Improvements

✔First system to unify aerial, ground AND water-surface detection simultaneously.
✔Real-time WebSocket dashboard to any browser — no cloud or app needed.
✔Non-blocking millis() firmware for concurrent sensing, sweep & streaming.
✔Single ESP32 + one HC-SR04 under ₹1,500 total.
✔TTP223 touch override — manual alert activation, unique to this architecture.

Problem Statement & Objectives

Existing intrusion detection systems monitor only a single environment. No low-cost embedded solution simultaneously covers ground, aerial & water domains with real-time IoT dashboard monitoring.

Research Objectives

1Design cost-effective multi-sensor IDS using a single ESP32.✔
2Detect intrusions in aerial, ground & water domains simultaneously.✔
3Audible alert within 100ms via active piezo buzzer.✔
4180° bilateral scanning via SG90 servo motor.✔
5Manual override via TTP223 capacitive touch sensor.✔
6Stream live radar data to WebSocket dashboard on local Wi-Fi.✔
7Non-blocking firmware using millis()-based timing throughout.✔
8Validate via physical prototype & real-world intrusion scenarios.✔

Proposed System & Hardware

Components integrated into the physical prototype

1
ESP32 DevKit V1
Dual-core 240 MHz MCU with built-in Wi-Fi 802.11 b/g/n
GPIO varies

ESP32 DevKit V1

Specs: Dual-core Xtensa LX6 @ 240MHz, 520KB SRAM, 4MB Flash, Wi-Fi 802.11 b/g/n, BT 4.2, 38 GPIOs

GPIO: Multiple — TRIG: 5, ECHO: 18, Servo: 13, Touch: 26, Buzzer: 27

Role: Central MCU running FSM, WebSocket server & sensor orchestration

2
HC-SR04 Ultrasonic
Time-of-Flight sensor; 2–400 cm; mounted on servo for sweep
GPIO 5/18

HC-SR04 Ultrasonic

Specs: Range 2–400cm, 40kHz ultrasonic, 5V, accuracy ±3mm, 15° beam angle

GPIO: TRIG → GPIO 5 · ECHO → GPIO 18

Role: Primary distance sensing — detects ground, aerial & water-surface targets

3
SG90 Micro Servo Motor
0°–180° PWM bilateral radar sweep actuation
GPIO 13

SG90 Micro Servo Motor

Specs: Torque 1.8kg/cm, speed 0.1s/60°, 5V, PWM 50Hz, pulse 500–2400μs

GPIO: Signal → GPIO 13 (ledc channel 0)

Role: Rotates HC-SR04 through 0°–180° for bilateral radar sweep coverage

4
TTP223 Touch Sensor
Capacitive touch; active HIGH; manual alert override
GPIO 26

TTP223 Touch Sensor

Specs: Capacitive, 3.3–5V, active HIGH output, 1μA sleep, response <60ms

GPIO: OUT → GPIO 26 (digital input, pulled LOW)

Role: Manual alert override — forces FSM into ALERT state on touch press

5
Active Piezo Buzzer 5V
Audible alert; HIGH = alarm; <100ms latency
GPIO 27

Active Piezo Buzzer 5V

Specs: Active type (internal oscillator), 5V, ~85dB @ 10cm, 2kHz tone

GPIO: + → GPIO 27 via NPN transistor · GND → common ground

Role: Immediate audible alert on intrusion detection (<100ms from FSM trigger)

System Architecture

Three-layer design: Sensing → Processing → Output/Alert with FSM control

SENSING
  • HC-SR04 Ultrasonic Sensor
  • SG90 Servo 0°–180° sweep
  • TTP223 Capacitive Touch
  • GPIO: 5, 18, 13, 26
→
PROCESSING
  • ESP32 Dual-Core 240 MHz
  • FSM: IDLE→SCANNING→ALERT→GATE
  • 100ms millis() polling cycle
  • AsyncWebServer + WebSocket
→
OUTPUT
  • Piezo Buzzer GPIO 27 <100ms
  • WebSocket JSON Broadcast

Key Test Findings
